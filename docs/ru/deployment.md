## Что работает в продакшене

`docker-compose.yml` запускает два контейнера:

| Сервис  | Образ                                    | Роль                                                                          |
| ------- | ---------------------------------------- | ----------------------------------------------------------------------------- |
| `web`   | `kyuar-web` (собирается из `Dockerfile`) | Standalone-сервер Next.js на порту 3000: Mini App, `/api/*` и webhook бота    |
| `redis` | `redis:8-alpine`                         | Лимиты запросов и готовые изображения. Только в памяти, 64 MB, вытеснение LRU |

Отдельного контейнера для бота нет. Telegram отправляет обновления на `APP_URL/api/bot`, и их обрабатывает веб-приложение.

У образа нет аргументов сборки и переменных `NEXT_PUBLIC_*`. Вся конфигурация приходит из `.env` во время работы, поэтому один образ работает в любом окружении, и ни один секрет не попадает в слой образа.

## Требования к серверу

- Docker с Compose
- Публичный HTTPS-адрес, который ведёт на порт 3000

## Первое развёртывание

1. Скопируйте репозиторий на сервер и создайте `.env`:

   ```bash
   cp .env.example .env
   ```

2. Заполните `.env`. Переменные перечислены в разделе [Архитектура → Конфигурация](architecture.md#конфигурация). В продакшене:

   - `APP_URL` должен начинаться с `https://`. Иначе проверка не пройдёт.
   - `REDIS_URL` задавать не нужно. Compose ставит его равным `redis://redis:6379`.
   - `BOT_WEBHOOK_SECRET`: сгенерируйте через `just secret`.

3. Соберите и запустите:

   ```bash
   just docker-build
   just docker-up
   ```

4. Проверьте состояние. Веб-контейнер здоров, когда `/api/qr?d=health` возвращает изображение:

   ```bash
   docker compose ps
   just docker-logs web
   ```

5. Направьте Telegram на сервер и опубликуйте меню команд. Это запускается с машины, где есть репозиторий и тот же `.env`:

   ```bash
   just webhook-set
   just webhook-info
   ```

6. Настройте BotFather, как описано в разделе [Telegram-бот → Настройка BotFather](bot.md#настройка-botfather).

## HTTPS

Telegram открывает Mini App и отправляет webhook только по HTTPS. Два частых варианта:

- **Обратный прокси** (Caddy, nginx) на сервере с сертификатом, который перенаправляет на `localhost:3000`.
- **Cloudflare Tunnel**: создайте в Cloudflare именованный туннель на `http://localhost:3000` и запустите `cloudflared` на сервере. Открытые порты не нужны.

Поставьте кэш перед `/api/qr`. Маршрут отдаёт `Cache-Control: public, max-age=31536000, immutable`, поэтому повторный код не доходит до Node.

Если прокси передаёт IP клиента не в `X-Forwarded-For`, а в другом заголовке (например, `CF-Connecting-IP`), задайте `CLIENT_IP_HEADER`. Иначе у всех пользователей будет один общий лимит.

## Redis

| Ключ                         | Назначение                                                          | Время жизни |
| ---------------------------- | ------------------------------------------------------------------- | ----------- |
| `rate:<scope>:<ip>:<window>` | Число запросов клиента за минуту                                    | 60 s        |
| `render:<id>:<format>`       | Готовые PNG, PNG 2048 px, JPEG и SVG кода с логотипом или картинкой | 600 s       |

Redis не хранит ничего постоянного, поэтому работает без сохранения на диск. Если его потерять, ничего важного не пропадёт.

Без Redis:

- Лимиты запросов выключены. Все запросы разрешены.
- В Telegram отправка и скачивание кода с логотипом или картинкой падают с 503, потому что Telegram нужен URL, откуда взять изображение.

Обычные коды по-прежнему работают через `/api/qr`.

## Безопасность

- **initData.** `/api/share` и `/api/render` проверяют `initData` Telegram токеном бота и отклоняют данные старше одного часа. Личность пользователя берётся только из проверенных данных.
- **Webhook.** `/api/bot` отклоняет запросы без правильного `X-Telegram-Bot-Api-Secret-Token`.
- **Загруженные изображения.** sharp декодирует и заново кодирует каждый логотип и картинку с лимитом пикселей, прежде чем они попадут в SVG.
- **Заголовки.** Приложение отправляет `X-Content-Type-Options: nosniff`, строгую политику referrer и `frame-ancestors`, который разрешает только Telegram Web.
- **Контейнер.** Веб-приложение работает от непривилегированного пользователя `nextjs`.

## Обновление

```bash
git pull
just docker-build
just docker-up
```

Compose заменяет веб-контейнер. Redis продолжает работать. Запускайте `just webhook-set` снова, только когда меняется `APP_URL` или команды бота.

## Решение проблем

| Признак                           | Что проверить                                                                                     |
| --------------------------------- | ------------------------------------------------------------------------------------------------- |
| Контейнер перезапускается         | `just docker-logs web`. Обычно в `.env` нет переменной или она неверна                            |
| Бот молчит                        | `just webhook-info`: URL должен быть `APP_URL/api/bot`, а `last_error_message` должен быть пустым |
| У inline-результатов нет картинок | `/api/qr` должен быть доступен из интернета по HTTPS                                              |
| Отправка падает с 503             | Redis недоступен                                                                                  |
| Все получают 429                  | `CLIENT_IP_HEADER` не совпадает с прокси                                                          |
